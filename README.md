# Bridge Lab v0.2

A browser-based classroom bridge designer. Draw joints and members, choose profiles, run a moving truck test, inspect axial forces, bending and member failures, and compare material cost.

## Run with Docker

1. Copy `.env.example` to `.env` and replace `BRIDGE_SETUP_TOKEN` with a long random setup key. This key authorizes creation of the first administrator; it is separate from your chosen administrator password.
2. Start the app:

```bash
docker compose up -d --build
```

3. Open **Classroom** and create your administrator account. Enter the setup key from `.env`, a username, and a password of at least 10 characters. Once an administrator exists, the setup page is closed.
4. Create teacher accounts in Classroom and give each teacher their username and initial password. Teachers can change their own passwords after signing in.

Open **http://localhost:8095** (or your server's IP on port 8095). Change the left side of the port mapping in `compose.yaml` if needed. The Node server stores accounts, classes, challenge drafts and assignments in SQLite under the bind mount **`./data`**. Keep that folder when upgrading, and back it up with the container stopped. Bridge work on the drawing board and local Save/Open designs still live in browser storage; Export/Import moves those designs between devices.

With Nginx Proxy Manager or another trusted HTTPS reverse proxy, set `TRUST_PROXY=1` in `.env` so the server recognizes the HTTPS origin and sends secure session cookies. Keep the proxy's original Host and X-Forwarded-Proto headers. For direct HTTP access, leave it at 0.

For local development, set `BRIDGE_SETUP_TOKEN` in the environment and run `npm run serve`. The default address is http://localhost:8095. Run checks with `npm test`. The Docker image needs no npm installation; its runtime uses Node 24 built-in SQLite.

## How to use

1. Start with the provided truss or select **New** for a fixed deck and supports.
2. Use **Joint** to place points on a 1 m grid. **Member** connects two points; a member passing through an existing joint stays disconnected; a dashed ! marker identifies the open connection. Stronger/deeper profiles draw thicker, and aluminum has a teal material edge. During testing, a narrower force-color overlay preserves the tension/compression/bending display. Free joints can be dragged using **Select**. Deck/support joint positions are fixed in the editor; only the actual supports restrain structural movement.
3. Pick a member profile. Select one or several members to change their profile. Shift-click or drag a selection box to select multiple members and joints. Drag a selected free joint to move selected free joints together. **Delete selected** removes the chosen parts; **Clear design** removes all members and free joints while retaining the deck and supports. Undo restores either action.
4. **Test bridge** animates a tractor trailer crossing. Drag the position slider to inspect any point of the run. Toggle **Show member capacity %** below the board to label each member with its combined demand as a percentage of its capacity during a stable test. Click a member to see axial force, bending moment, shear, stress, utilization, and buckling load. Choose Beams + bending (default) or Pin-jointed truss. Select joints to choose rigid moment transfer or a freely rotating hinge; hinges have an outer ring.
5. Open **Classroom** to sign in. Administrators create, reset and enable/disable teacher accounts. Teachers manage their own classes and challenge drafts. Choose **Create a challenge**, prepare the bridge, and use **Challenge settings** to enter instructions, an optional budget, span (5–100 m), structural model, road weight per metre, force units (N, kN, lbf, kip, kgf), and a load type. Choose 1–5 moving trucks with front-to-front spacing of 8–100 m, a stationary center load, or both. Axle loads are per truck. Switching units converts the entered values. Changing span stretches the starter horizontally and keeps its connections. Saving applies the settings to the board. **Save to classroom** stores the draft on the server. Assign it to a class in Classroom, then copy its URL (for example `/design-7a/challenge-1`). Students open the URL without accounts. A class URL such as `/design-7a` lists its assigned challenges. Older URLs containing generated codes redirect to the readable format. Class names must produce distinct URLs across the site; assigned challenge titles must produce distinct URLs within a class. Assigned challenges keep a snapshot of the starter and goals; use **Assign / update** to publish draft changes while keeping the URL. **Unassign** removes student access to that assignment. Disabled teachers' class links are unavailable until re-enabled.
6. **Save locally** and challenge JSON import/export remain available for portable/offline copies. Student attempts are saved per assigned challenge in that browser and survive reloads while the starter is unchanged. If the teacher publishes a different starter, the next reload opens that starter. Attempts are not submitted to the teacher; student accounts and submissions are not part of this version.
7. Use **Save/Open** on this device, or **Export/Import** to move bridge designs between devices. Undo/redo shortcuts: Ctrl+Z/Ctrl+Y. Drawing shortcuts: V/J/M/E.

## Simulation assumptions

- The default is a road-bearing 2D Euler–Bernoulli elastic frame: axles load deck members between joints, members have axial and bending stiffness, joints are rigid unless explicitly hinged, and supports are a left pin/right roller. Optional ideal-truss mode transfers roadway loads to panel joints and checks axial force only. Utilization percentages from the two modes therefore measure different demand and should not be compared as though only the joint symbol changed. Older files without a model field keep their original truss behavior.
- Distributed member self-weight and road weight (default 1.6 kN/m), plus a 40 kN front and 120 kN rear axle separated by 4 m. Teachers configure the road weight, trucks, spacing, span and static center load. Point loads inside deck beams produce bending using consistent element loads. Where no deck beam exists, the road distributes load to neighboring joints but supplies no structural stiffness. Truss mode always distributes loads to joints.
- Moving tests check global positions, axle/joint crossings, and eight local positions per deck interval per axle in frame mode. This is a sampled quasi-static envelope, not an exact worst-case search; inertia, impact and vibration are not simulated.
- Frame yield demand combines peak axial-plus-bending normal stress with a conservative shear envelope (twice average shear). The square-tube section depth sets its bending section modulus. Compression uses an ideal Euler estimate (full collinear unbraced chain length, weakest EI, and a length factor of 2 at a free end) with a linear compression/bending interaction. These are educational approximations, not a steel design-code check; global frame buckling, lateral instability and second-order effects are not calculated.
- Elastic motion over 5% of a member length or joint rotation over 0.1 rad is a serviceability failure: the bridge remains standing and the app asks the student to stiffen it. If a member reaches capacity at the same load, the specific yield or buckling result takes priority. The test stops at the first sampled capacity exceedance or unresolved result. Yielding means permanent deformation begins, not fracture: yielded members remain continuous and amber; buckled members turn red and bow. Elastic member and road curvature follow the solved bending deformation.
- First yield stops the test and marks permanent deformation, but the member remains continuous and the bridge does not collapse. For buckling, a conservative alternate-load-path check removes the buckled member’s stiffness, retains its weight, and re-solves the same load. It repeats if redistribution buckles more members. A damaged bridge fails the challenge even if it remains standing.
- If the remaining structure has a free movement, a five-second fall illustrates the affected joints only. Unused, unloaded, non-deck joints are ignored; loaded/deck joints still require a load path. Numerical/invalid-input errors do not imply a collapse. In truss mode, pass-throughs are identified as contributors only when a hypothetical connection reduces the number of free modes; the student's design is never automatically joined.
- The buckled-member check is conservative, not a nonlinear plastic or fracture calculation. Real buckled members can retain some capacity. Its unstable verdict does not prove actual collapse. Elastic deflection is drawn without amplification. The direction, duration, geometry and water impacts of a collapse are illustrations rather than computed dynamics.
- Cost is an illustrative **material-only** estimate from member mass and a rate per kg. It excludes fabrication, joints, deck, foundations, and construction.
- Members connect only at their endpoints. A dashed ! marks a member passing through a joint without connecting; replace it with two members if that joint should carry force. Two lines crossing without a joint do not transfer force. Unstable designs get a persistent on-bridge explanation and highlighted joints during the illustrative fall, including failures before the truck starts moving. For a bracing mechanism, the highlighted joints and two-way arrows come from a free-motion calculation that preserves member lengths to first order; they are not inferred from a failed matrix pivot. If missing bottom-chord members account for the mechanism, the app marks their deck spans and explains that the drawn roadway carries no truss force. For an unstable truss the solver has no trustworthy member forces, so no member is claimed to have snapped.

This is an educational model, **not a design tool for real structures**. In particular, it does not model a separate roadway slab, connection strength failures, 3D lateral bracing, fatigue, code safety factors, plastic redistribution, or nonlinear dynamic collapse.
